# Agent Video Workbench 0.4.0

These notes describe the current source. The publisher requires successful native Linux
x86_64 and ARM64 qualification of the exact source commit, including the
required media and agent workflow summaries, before publication.

## Creator workflows

- Preserve supported plain-cut Rec.709, 10-bit PQ and HLG source color in a
  verified master, with a separately labeled SDR review preview when required.
  Paper-edit planning records the brief, cut reasons, speech-boundary review
  and source-context preview requests. Captioned or otherwise composed output
  remains SDR.
- Search reviewed transcript cues across cue boundaries, optionally using
  canonical Unicode matching or joining without spaces. Page bounded source
  evidence and prepare editable highlight plans from caller-supplied proposals.
  An optional configured analysis provider can return source-bound search
  candidates; its interpretation remains a proposal for review. The workbench
  does not bundle a semantic or visual understanding model.
- Return verified source frames, render contact sheets and short proxy-audio
  excerpts through the optional `avw-media` MCP content tool. The equivalent
  `agent-media` operation is available through CLI/JSON. Whether a host exposes
  image or audio blocks to its model depends on that host.
- Preview and accept separately supplied word-alignment proposals while
  retaining the reviewed transcript and binding the result to source and
  transcript identities. Review caller-supplied caption translations against
  the frozen source captions and retain asserted provider provenance with an
  editable language variant. Reframing can prepare editable crop proposals
  from explicitly supplied subject observations. These features do not
  independently translate, detect words, people or objects, or establish
  translation accuracy; review remains necessary.
- Compare verified queued plain-cut renders by source range; draft public
  chapters from selected frozen markers. Delivered review pages support
  timestamped feedback drafts and decisions that can be imported against the
  frozen artifact. Layered visual/audio comparison remains outside the
  plain-cut comparison contract.
- Check user-supplied delivery briefs for an individual render or batch and
  package results with caller-authored metadata. Per-output pass, fail and
  unknown results do not establish upload acceptance, editorial quality or
  caption accuracy. Create thumbnail candidates from user-selected times in
  the verified review video; selection and visual approval remain with the
  creator. The tool does not publish to social platforms.
- Opt into per-item FFmpeg spectral noise reduction on supported composed
  outputs. Settings are reversible and reported with the render; listen for
  changed speech or transients and check A/V sync. A generated fixture measured
  about 20 ms of added onset delay, not a guarantee for other media. This is
  not a speech-isolation model and is not applied to source-preserving or
  nested output paths.

The workbench continues to retain originals, edit history and retry outcomes;
existing artifacts are not silently rewritten. Sidecar export rejects visible
captions that collapse at millisecond precision. Review intervals use recorded
verified render timing, including explicitly sized sequences. Older static
review pages need a newly generated package for the updated controls.

Legacy `delivery` packages include full frozen project snapshots and may
include project reviews, transcripts and other private notes. New
`batch-delivery` packages use minimized manifests and omit those project
snapshots and saved review notes. Inspect either type before sharing: selected
project, sequence and artifact IDs, media, captions, contact sheets and
caller-supplied metadata can still contain sensitive information.
On Unix, checked batch destinations are owner-only. A process crash can leave
an owner-only `.avw-batch-*.incomplete` staging directory containing broader
project data; remove abandoned staging directories locally.

## Installation and limits

The intended release archives target glibc-compatible Linux x86_64 and ARM64.
The native binary uses FFmpeg/ffprobe 8, supplied separately; caption rendering
also needs an imported licensed font. Optional local transcription requires a
separately installed provider and model. The installed binary does not require
Node, Cargo, a GUI or root; Node and Chromium are test clients.

`host-readiness` runs local workspace, free-space and configured FFmpeg checks.
It leaves host persistence, account compatibility and model image/audio
consumption unknown until those properties are tested in the actual host.

Qualification uses generated media and browser viewport emulation. Real
creator acceptance, physical-phone and HDR appearance, arbitrary camera
profiles, broader language/script accuracy, macOS/Windows and specific hosted
agent accounts need separate validation. HDR composition, grading and burned
captions are not part of the source-preserving HDR path. Read the bundled
`docs/implementation-status.md` and `AGENT_GUIDE.md` for supported scope,
recovery and limitations.
